# Investigation profile selection and editing

Verified September 27, 2026.

A controlled reproduction of the actual InvestigationProfiles and ProfileEditor callbacks found a wrong-target revision request. An Alpha inspection remained pending while Bravo loaded and its editor opened. When the older Alpha response arrived, the workbench selection changed to Alpha while the editor retained Bravo's definition. Saving then addressed Alpha's revise endpoint with Alpha's revision and Bravo's definition. The proof used request stubs only; no saved profile or native data was changed. The original script and result are retained outside the submission as `research/harbor-profile-edit-race-audit.mts` and `.json`.

Inspection responses now belong to a monotonically increasing selection request. Older success, error and finally callbacks cannot replace a newer selection, display its error or clear its busy indicator. Unmount invalidates outstanding selections. Status and save operations also participate in this ordering so their late responses cannot replace a later selection. This does not cancel a dispatched mutation or claim it failed: the list reload still reads its result.

An editor separately retains the ID and revision present when Edit profile was opened. Its save uses that pair rather than the current workbench selection. The server's existing revision check still handles conflicting changes; the client does not silently adopt a later revision. New, imported, template and duplicated definitions clear the edit target and keep their existing creation behavior.

## Current access and recovery

A denied or missing saved profile is removed from the current view and exports, including an edit, duplicate or start-investigation form derived from it. A denied list read clears its saved profiles. A refusal for another profile does not clear an independently authorized selection.

A temporary read failure hides the affected details and form until **Read profile again** succeeds. The mounted form retains its inputs, and the editor or start form keeps the ID and revision originally opened. A list refresh alone does not confirm access to a retained detail draft. **Check access again** retries an unavailable list. New, imported and built-in-template drafts remain independent of saved-profile access.

After a refused revision, status change or start request, Harbor checks current read access once. That check does not resend the write. A received successful save is still reported as saved when refreshing the surrounding list fails. Server permission and revision checks are unchanged.
